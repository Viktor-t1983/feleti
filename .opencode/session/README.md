# Система сохранения контекста между сессиями (Session Persistence)

> **Цель:** Любая новая сессия LLM должна за 2-3 минуты понять, где мы, что работает, что сломано, и что делать дальше.

## Проблема

LLM-сессии не имеют общей памяти. Контекстный окно ограничено (~128K токенов). При сжатии контекста система может потерять критические детали.

## Решение: "Файлы как память"

Вся важная информация должна быть **в файлах проекта**. Агент читает файлы → понимает контекст → работает → записывает изменения → коммитит.

## Структура

```
.opencode/
├── AGENTS.md                    # Entry point — роли, скиллы, правила
├── session/
│   ├── README.md               # Этот файл — описание системы
│   ├── TEMPLATE.md             # Шаблон начала новой сессии
│   ├── CHECKLIST.md            # Чек-лист конца сессии
│   └── history/                # Архив сессий (auto-generated)
│       ├── 2026-06-03_0937_session_6.md
│       └── ...
└── skills/                     # 19 SKILL.md — компетенции агента
```

## Протокол работы

### В начале сессии (3 минуты)

1. Прочитать `AGENTS.md` — кто я, какие роли, какие скиллы
2. Прочитать `docs/PROJECT_BOOT.md` — цели проекта
3. Прочитать `docs/CONTEXT_HANDOFF.md` — что было в прошлой сессии
4. Прочитать `CHANGELOG.md` — что реально сделано
5. Прочитать `TODO.md` — что в планах
6. Проверить `git log --oneline -10` — последние коммиты
7. Проверить `docker compose ps` — что запущено
8. Запустить `python scripts/verify_context.py` — проверка целостности

### В конце сессии (5 минут)

1. Обновить `CHANGELOG.md` — что сделано в этой сессии
2. Обновить `TODO.md` — отметить выполненное, добавить новое
3. Обновить `docs/CONTEXT_HANDOFF.md` — сводка последней сессии
4. Обновить `docs/PROJECT_BOOT.md` — текущий статус
5. Создать запись в `.opencode/session/history/YYYY-MM-DD_HHMM.md`
6. Сделать `git add -A && git commit -m "..."`
7. Запустить `python scripts/verify_context.py` — всё на месте?

## Session History файл

Каждая сессия создаёт файл `.opencode/session/history/YYYY-MM-DD_HHMM.md`:

```markdown
# Сессия от 2026-06-03 09:37

## Что сделано
- [x] Пункт 1
- [x] Пункт 2

## Файлы изменены
- `backend/app/models/...`
- `frontend/...`

## Тесты
- [x] Все тесты проходят
- [ ] Тесты не запускались

## Следующие шаги
1. ...
2. ...

## Блокеры
- ...

## Коммит
`8319d7f` — описание
```

## Восстановление после потери контекста

Если сессия оборвалась или контекст потерян:

1. Найти последний `history/` файл — он содержит полную сводку
2. Прочитать `CONTEXT_HANDOFF.md` — там приоритеты
3. Проверить `git status` — есть ли незакоммиченные изменения
4. Запустить `docker compose ps` — что работает
5. Продолжить с чек-листа TODO.md

## Правила золотые

1. **Всё в файлах.** Если информация только в памяти — она потеряна.
2. **Коммит после каждой сессии.** Всегда. Даже если "ничего не работает".
3. **CHANGELOG — истина.** Всё, что не в CHANGELOG, не существует.
4. **TODO — живой документ.** Приоритеты меняются — TODO обновляется.
5. **SKILL.md — единый источник.** Правила в SKILL.md важнее правил в промпте.
