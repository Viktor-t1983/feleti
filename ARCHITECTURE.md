# FELETI-SMOK: Архитектура Knowledge Core

## Цель
Построить систему, где каждый факт о копчении имеет происхождение,
подтверждение и контекст. Система понятна человеку, эффективна для AI,
надёжна для промышленного использования.

## План реализации (фазы)

### Фаза 1: Диагностика
Проверить:
- Сколько фактов накопилось
- Сколько статей переанализировано
- Качество фактов (есть ли source_text, правильно ли определены subject/object)
- Работает ли profile API

### Фаза 2: Чанкинг
**Проблема**: AI анализирует всю статью целиком (до 20000 символов).
Контекст большой, промпт размытый, source_text неточный.

**Решение**:
1. При импорте/сохранении статьи резать `body_md` на чанки по 2000 символов
2. Overlap 200 символов между чанками (чтобы не потерять контекст на стыке)
3. AI анализирует каждый чанк отдельно
4. source_text привязан к конкретному чанку (char_offset)

**Файлы**:
- `backend/app/services/chunker.py` — логика нарезки
- `backend/app/services/article_analyzer.py` — анализировать чанки, не всю статью
- `backend/app/models/knowledge_fact.py` — уже есть chunk_id

**Риски**:
- Больше запросов к API (1 статья = N чанков × 1 запрос)
- Решение: батчим чанки в один запрос или консолидируем

### Фаза 3: Наследование фактов
**Проблема**: Факт для «Лососёвые» не применяется к «Горбуша».

**Решение**:
- Резолвер при запросе profile поднимается по parent_id
- Факты родителя наследуются детям
- inherited: true в ответе API

### Фаза 4: Матрица совместимости на фактах
**Проблема**: `compatibility_matrix.py` — хардкод, не обновляется.

**Решение**:
- Запрос: `SELECT * FROM knowledge_facts WHERE predicate IN ('uses_brine', 'uses_equipment', 'uses_technology')`
- Группировка по product_id → список рассолов/камер/технологий
- Полностью динамическая, обновляется при добавлении фактов

### Фаза 5: Верификация
**Проблема**: Все факты от AI — кандидаты. Нет механизма подтверждения.

**Решение**:
- UI на странице продукта: кнопки подтвердить/отклонить факт
- Статусы: candidate → confirmed | contradicted | deprecated
- Multi-source confidence: один факт из N источников → confidence = min(0.3 + N*0.2, 0.95)

### Фаза 6: PDF-загрузчик
**Проблема**: Профессиональные книги — основной источник знаний, но их нельзя загрузить.

**Решение**:
- Drag-and-drop PDF
- PyMuPDF (fitz) для извлечения текста
- Чанкинг → AI-анализ → факты
- Хранение PDF в MinIO

---

## Принципы

1. **Source-first**: каждый факт обязан иметь source_text
2. **Confidence**: чем больше источников, тем выше уверенность
3. **Human-in-the-loop**: AI предлагает, человек подтверждает
4. **Inheritance**: факты родителя → детям
5. **Dynamic**: никакого хардкода, всё из БД
