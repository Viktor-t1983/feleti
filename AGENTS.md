# Директивы AI-агента (opencode)

## Роль и поведение

Я — **главный технолог копчения + ведущий архитектор платформы FELETI-SMOK**. Мои правила:

1. **Сам веду процесс** — не спрашиваю «что делать дальше», а выбираю следующую задачу из плана, докладываю и начинаю делать. Если нужен выбор — предлагаю варианты, но решение принимаю сам и аргументирую.
2. **Архитектурная ответственность** — не упрощать, если потом придётся переделывать. Ошибки исправлять сразу.
3. **Документация** — `STATUS.md` и `AGENTS.md` веду актуально после каждого изменения. Это моя компетенция, не пользователя.
4. **Партии (batches)** — не трогать, это последняя задача.
5. **Ответы на русском**, если пользователь пишет на русском.
6. **Приоритет пользователя** — он владелец платформы. Я исполнитель и советник. Но в рамках проекта я ведущий разработчик, беру задачи и делаю.

# AI-агент сбора знаний о копчении. Архитектура, источники, план

## 1. Конечная цель: единая платформа знаний «Всё о копчении»

Платформа должна стать **исчерпывающим источником знаний по промышленному копчению** на русском языке, с AI-интерфейсом, который:

- Отвечает на вопросы технолога (RAG по базе знаний + LLM)
- Самостоятельно собирает информацию из открытых источников
- Структурирует знания в семантическое дерево
- Связывает все сущности: сырьё → посол → рецепт → оборудование → режим → результат
- Анализирует конкурентов и рынок
- Помогает в диагностике проблем и оптимизации производства

## 4. Архитектура агента сбора знаний

```
┌──────────────────────────────────────────────────────────┐
│                  UI / Чат-ассистент                       │
│  (Пользователь задаёт вопрос, запускает сбор)            │
└──────────────────────┬───────────────────────────────────┘
                       │ POST /ai/collect {query, source_type}
                       ▼
┌──────────────────────────────────────────────────────────┐
│               Knowledge Collection Agent                  │
│  (оркестратор, управляет пайплайном)                     │
│                                                          │
│  1. Принимает запрос: /collect осётр холодного копчения  │
│  2. Определяет:                                         │
│     - Какие узлы дерева релевантны (→ /Сырьё/Рыба/Осётр) │
│     - Какие источники искать (сайты, YT, TG)            │
│  3. Запускает параллельные задачи:                      │
│     - web_crawler по целевым сайтам                     │
│     - youtube_transcriber по ключевым словам             │
│     - telegram_parser по каналам                       │
│  4. Каждый результат → LLM extractor                    │
│  5. Результат → KnowledgeArticle + привязка к дереву    │
│  6. SSE-прогресс: "3/12 источников обработано"          │
└──────────────────────────────────────────────────────────┘
```

### 4.1 Компоненты агента

#### A. Коллектор (то, что есть)
- `web_crawler.py` — берёт HTML, чистит, достаёт текст + метаданные
- `youtube_transcriber.py` — скачивает субтитры с YouTube
- `telegram_parser.py` — парсит Telegram-каналы через Telethon
- `knowledge_pipeline.py` — объединяет всё в CrawlResult → ExtractedData

#### B. Экстрактор (то, что есть)
- `llm_extractor.py` — через LLM извлекает структуру: продукты, технологии, проблемы
- `article_analyzer.py` — анализ + topic_path + категоризация

#### C. Оркестратор (то, что нужно доделать)
- Принимает запрос /collect
- Определяет, какие источники и ключевые слова использовать
- Запускает параллельный сбор
- Отслеживает прогресс
- Сохраняет результат

### 4.2 Поток данных

```
1. Запрос: "собери информацию про осетра х/к"
       │
2. Анализ запроса (LLM):
   - Ключевые слова: осётр, холодное копчение
   - Узлы дерева: /Сырьё/Рыба/Осётр, /Технологии/Копчение/Холодное
   - Источники: vseokopchenii.ru, YouTube, Telegram
       │
3. Параллельный сбор:
   ├─ Сайт 1: vseokopchenii.ru/search?q=осётр → CrawlResult
   ├─ Сайт 2: smokehouse.ru/search?q=cold+smoking+sturgeon → CrawlResult
   ├─ YouTube: "холодное копчение осетра" → субтитры → CrawlResult
   └─ Telegram: сообщения по ключевым словам → CrawlResult
       │
4. Для каждого CrawlResult:
   ├─ De-duplication (SimHash) — пропустить если уже есть
   ├─ Quality gate — min длина, source reputation
   └─ LLM Extraction → ExtractedData (структура)
       │
5. Сохранение:
   ├─ KnowledgeArticle (title, body_md, source_url)
   ├─ ArticleAnalysis (products, technologies, equipment, topic_path)
   ├─ Связь с деревом (article_topics)
   └─ Если есть упоминания конкурентов — связь с competitor
       │
6. Чат:
   └─ После сбора: "Собрано 5 статей по осетру. Спрашивай!"
```

### 8.2 API агента

```python
# Запуск сбора
POST /api/v1/ai/collect
{
    "query": "осётр холодного копчения",
    "source_types": ["web", "youtube", "telegram"],  # опционально
    "topic_ids": [18, 7],  # опционально (узлы дерева)
    "max_results": 20
}
→ {
    "collection_id": "uuid",
    "status": "running",
    "sources_queued": 12
}

# Прогресс (SSE)
GET /api/v1/ai/collect/{id}/progress
→ event: progress
  data: {"processed": 5, "total": 12, "status": "running"}
→ event: article
  data: {"id": 42, "title": "...", "topic_path": "..."}
→ event: done
  data: {"articles_created": 5, "articles_skipped": 2}
```

### 8.3 Quality gate (фильтрация)

```
Входящий CrawlResult
  ├─ Длина текста > 100 символов?        НЕТ → SKIP
  ├─ De-duplication (SimHash + title)?   ДА  → SKIP
  ├─ Source reputation:
  │   ├─ Известный домен        → score +3
  │   ├─ Неизвестный домен      → score 0
  │   └─ Чёрный список          → SKIP
  ├─ Contradiction check (LLM)?
  │   "Противоречит ли этот текст   ДА → пометить "спорно"
  │    существующим статьям?"            
  └─ Сохранить с confidence = score / max_score
```

## 9. Что забыл — дополнения

На основе того, что уже есть в проекте, я вижу, что не хватает:

1. **Репутация источников** — таблица `source_reputation` с доменами и уровнем доверия
2. **История диалогов** — таблица `chat_sessions` + `chat_messages` для сохранения контекста
3. **Knowledge Graph** — таблица `entity_links` (article_id, entity_type, entity_id, relation_type)
4. **Photo-диагностика** — нейросеть для оценки продукта по фото (пересол/недосол/горечь)
5. **Scheduled сбор** — APScheduler для периодического краулинга
6. **Матрица совместимости** — recommendations ML на основе истории партий + рецептов
7. **Telethon сессия** — для telegram_parser нужно хранить сессию авторизации
8. **Миграция topic_path** — перенос старых analysis.topic_path в article_topics
