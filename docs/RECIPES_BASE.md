# FELETI-SMOK — Структура базы рецептов

> **Зачем:** единый формат для хранения рецептов, версионирования, расчёта БЖУ/себестоимости и шаринга.
> **Источники:** ГОСТы, каталоги Ижица/Fessmann/Kerres, рецепты технологов, база знаний.

---

## 1. Модель данных (упрощённо)

```
Recipe
  ├── id, name, slug, product_id, current_version_id
  └── status: draft | pending | approved | archived

RecipeVersion (иммутабельная!)
  ├── version_number (1, 2, 3, ...)
  ├── parent_version_id (для diff)
  ├── program: ProgramPhases[]    # программа копчения
  ├── brine: BrineRecipe          # посол
  ├── ingredients: RecipeIngredient[]
  ├── yield_percent, losses_percent
  ├── notes
  ├── created_by, created_at
  └── status (копия Recipe.status)

ProgramPhases
  ├── index (0..N)
  ├── name (Подсушка / Копчение / Варка / Охлаждение / ...)
  ├── duration_min
  ├── target_t_chamber, target_t_product
  ├── humidity_percent
  ├── smoke (none | light | medium | heavy)
  ├── wood_species (ольха | бук | дуб | яблоня | вишня | ...)
  ├── wood_form (щепа | опилки | стружка)
  ├── electro_voltage_kv (опц., 0 = выкл)
  ├── electro_current_ua (опц.)
  ├── fan_speed_percent
  ├── door_open_policy
  └── transition: time | product_temp | delta_t

BrineRecipe
  ├── method (сухой | мокрый | шприцевание | комби)
  ├── salt_percent, sugar_percent
  ├── nitrite_ppm, nitrate_ppm
  ├── spices[]
  ├── duration_hours
  ├── temp_c
  └── notes

RecipeIngredient
  ├── ingredient_id, weight_g, percent
  └── note (например, "в фарш", "в оболочку", "для орошения")
```

## 3. Древесина для копчения (reference)

| Порода | Вкус/аромат | Лучше для | Цвет | ГОСТ/примечание |
|---|---|---|---|---|
| **Ольха** | Мягкий, нейтральный, классический | Рыба, курица, свинина, сало | Золотистый | Самый популярный |
| **Бук** | Нейтральный, чуть сладковатый | Колбасы, сыры, говядина | Жёлто-коричневый | Близок к ольхе |
| **Дуб** | Терпкий, насыщенный | Говядина, баранина, дичь, выдержанные колбасы | Тёмно-коричневый | Сильный аромат |
| **Яблоня** | Сладковатый, фруктовый | Свинина, птица, сыры | Золотистый | Деликатесный |
| **Вишня** | Сладковатый, лёгкий | Птица, свинина, сыры | Красно-коричневый | Деликатесный |
| **Груша** | Мягкий, сладковатый | Рыба, птица | Золотистый | Деликатесный |
| **Слива** | Терпкий, с лёгкой горчинкой | Свинина, говядина | Тёмный | Реже |
| **Можжевельник** | Хвойный, смолистый | Дичь, баранина | Тёмный | Ограниченно |
| **Кедр** | Хвойный | Рыба (особенно лосось) | — | Специфический |

**Нельзя:** хвойные с большим содержанием смолы (сосна, ель) — дают горечь и вредные вещества.

**Фракция:** щепа 4–8 мм, опилки 2–4 мм, стружка/крупная щепа для длительного копчения.

## 7. Расчёт БЖУ и себестоимости

### 7.1. Формула БЖУ на 100 г
```
protein = Σ (ingredient.weight * ingredient.protein_per_100g) / total_weight * 100
fat     = Σ (ingredient.weight * ingredient.fat_per_100g)     / total_weight * 100
carbs   = Σ (ingredient.weight * ingredient.carbs_per_100g)   / total_weight * 100
kcal    = protein*4 + fat*9 + carbs*4
```

### 7.2. Себестоимость
```
cost = Σ (ingredient.weight * ingredient.price_per_unit) / yield_weight
```

`yield_weight` = `Σ ingredient.weight * yield_percent / 100`.

### 7.3. Потери при копчении
- Холодное копчение рыбы: 8–15% (усушка).
- Горячее копчение рыбы: 5–10%.
- Варёные колбасы: −8% (привес за счёт воды) → yield 108%.
- Полукопчёные: −15–20%.
- Сырокопчёные: −30–40%.

### 7.4. План реализации
- `backend/app/services/recipe_calc.py` — функции `calc_bju`, `calc_cost`, `calc_yield`.
- Поля в `RecipeVersion`: `bju_per_100g` (jsonb), `cost_per_kg` (decimal).
- Пересчёт при сохранении версии + кнопка «пересчитать».

## 8. Иммутабельность и diff

### 8.1. Почему иммутабельность
- Аудит: можно доказать, **что именно** коптили 2 года назад.
- Безопасность: нельзя «случайно» испортить утверждённый рецепт.
- Workflow: новая версия создаётся, старая остаётся в архиве.

### 8.2. Создание новой версии
```
1. Пользователь открывает RecipeVersion v3 (approved).
2. Нажимает «Создать новую версию» → создаётся RecipeVersion v4 (draft, parent=v3).
3. Редактирует.
4. Нажимает «Отправить на апрув» → status: pending.
5. Технолог/админ апрувит → status: approved, Recipe.current_version_id → v4.
6. v3 становится archived (опц.).
```

### 8.3. Diff версий
- Backend: `GET /api/v1/recipes/{id}/versions/{v1}/diff/{v2}` → список изменённых полей.
- Frontend: side-by-side или unified diff.

## 9. Хранение

- Рецепты в Postgres (JSONB для `program`, `brine`, `ingredients`).
- Поиск — `pg_trgm` для фуззи по названию + `tsvector` для full-text по notes/body.
- RAG (для Copilot) — `pgvector` embeddings по `name + notes + body_md` (когда подключим AI).
